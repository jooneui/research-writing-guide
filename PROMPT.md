# Reusable writing prompt

Write a **[weekly meeting note / research paper / paper section]** for **[audience]** about **[project/question]**. Use the supplied sources and the rules below. Ask only for missing information that prevents an accurate draft; otherwise mark a gap explicitly.

## Shared rules

1. Identify the research question, the intended reader, and why the answer matters. Do not substitute a topic or activity for a question or claim.
2. For each substantive item, make the chain explicit: **Purpose** (what this work is meant to establish or do), **Why** (the question or decision this purpose serves), and **Deliverable** (the concrete artifact or comparison). Add **Result** and **Evidence** only when the work has been done. A file path alone identifies an artifact; explain what in it supports the result.
3. For each substantive finding, state a precise **Claim**, at least one **Reason** for accepting it, and the **Evidence** (specific figure, table, equation, computation, observation, or cited source) supporting that reason. Ask whether a reader would see *why* the reason supports the claim; explain that link when it is not obvious. Distinguish observation from interpretation. If support is absent, label the claim tentative or leave a gap; do not invent evidence.
4. Give the method, conditions, comparison basis, and source quality needed to interpret a result. State limitations, counterexamples, or alternative explanations when they matter. Address the strongest relevant objection, not every imaginable objection.
5. Choose one term per concept and use it consistently. Keep symbols, units, time periods, figure names, and citation style consistent. Do not change a source's technical meaning merely to vary wording.
6. Write explanations and meeting notes roughly **80% of the way toward ASD-STE100**: use short, direct sentences; put one main action or assertion in each sentence; name the actor when that helps; prefer active verbs; and use one term for one concept throughout. Define a technical term at first use. Mark an ambiguous source as unclear instead of guessing. Remove exaggeration, vague praise, and repetition. Do not enforce the standard's restricted dictionary or sentence limits on research prose. Preserve equations, accepted technical terms, uncertainty, and necessary qualifications.
7. Cite borrowed ideas, methods, data, quotations, and figures. Never invent a citation, measurement, completed experiment, or figure. Use the citation style required by the venue; if none is specified, use one style consistently and say which one.
8. Before finalizing, check whether each section supports the main question or claim, whether every figure is introduced and interpreted, whether scales and visual choices represent the data fairly, and whether the conclusion matches the evidence. Read each sentence once for ambiguity: replace unclear pronouns, unexplained abbreviations, and shifts in terminology. If a relationship remains hard to follow, add a small table or diagram tied to the same evidence.

## If the output is a weekly meeting note

- Write in **itemized sections**, one research purpose or decision per section. Do not convert the note into continuous narrative.
- Open each section with these labeled bullets, in this order: **(Purpose)**, **(Why)**, **(Deliverable)**. If there are several deliverables, list them and make one subsection for each. Under each deliverable, use **(Status)**, **(Result)**, **(Claim)**, **(Reason)**, **(Evidence)**, **(Limitation)**, and **(Next step)** where applicable. Each bullet should express one function. Omit an optional label if it has no content; never fill it with a guess.
- **(Why)** explains why the purpose matters, not merely why a task is convenient. **(Deliverable)** states the expected output and acceptance criterion. **(Evidence)** cites an existing artifact and the specific observation within it.
- If work is planned, state **(Status) Planned** and avoid past-tense findings. If completed, state the actual result even if it differs from the plan. One deliverable can support several findings; give each substantive finding its own claim–reason–evidence chain.
- When comparing figures, pair each source figure with a corresponding result under matched axes, units, assumptions, and legend. State which assumptions differ by design. Name any mismatch and its possible interpretations without asserting a cause beyond the evidence. Do not alter axis scales to exaggerate an apparent difference.

## If the output is a research paper

- Use the paper structure required by the target venue. In the outline or drafting notes, record the **purpose**, **why**, and **deliverable** for each section. In the finished paper, present these naturally in scholarly prose; do not put repetitive labels in every sentence.
- Introduce the established context, the specific question or gap, why answering it matters, and the main claim. Support the claim through sections organized by reasons and evidence. Each paragraph should have a clear point related to its section.
- Introduce each table and figure with the point it tests or supports. In the caption, identify variables, units, conditions, and source where needed. Interpret what the reader should see, including uncertainty and deviations.
- End with the supported conclusion, its limits, and the next question. Do not claim generality beyond the tested cases.
